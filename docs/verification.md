# 검증 절차

사용자가 **"검증해줘"**("확인해줘", "다시 검증" 포함)라고 하면 이 문서를 처음부터 다시 읽고 **0 → 7단계를 순서대로** 진행한다. 콘텐츠나 계산을 바꾼 작업은 요청이 없어도 커밋 전에 6단계까지 진행한다.

## 공통 원칙

- **이전 검증 결과를 믿지 않는다.** history.md에 "확인됨"이라고 있어도 이번에 다시 확인한다.
- 단계를 건너뛰거나 **동시에 실행하지 않는다.** 한 단계의 판정과 근거를 적은 뒤 다음 단계를 시작한다(2026-11-24에 1–4단계를 겹쳐 실행한 일이 있다).
- FAIL이 나오면 멈추고, 고친 뒤 **1단계부터 다시** 한다. "검증만" 요청받았으면 고치지 않고 나머지 단계까지 진행해 보고한다.
- 판정은 네 가지뿐이다.
  - **PASS**: 이번에 실행하거나 원문을 봤고, 근거(명령 결과, URL, 조항)를 댈 수 있다.
  - **FAIL**: 틀린 것을 확인했다.
  - **미확인**: 확인하지 못했다(원문 유료, 접속 불가, 실행 못 함). 이유를 적는다. PASS로 세지 않는다.
  - **해당 없음**: 이유를 한 줄 적는다.
- 눈으로 읽은 것을 "계산했다", "테스트했다"고 쓰지 않는다. 기억은 근거가 아니다.
- 결과를 받기 전에 history.md나 보고에 "통과"를 미리 쓰지 않는다.
- 통과시키려고 검사 기준을 낮추거나 문구를 맞추지 않는다.

## 0단계. 범위 정하기

1. 범위는 사용자가 지정한 것. 지정이 없으면 `git diff`(커밋 전) 또는 이번 작업 커밋의 변경 파일.
2. 바뀐 **페이지, 공식, 수치, 주장**을 목록으로 만든다.
3. 각 수치·주장이 나오는 **다른 위치**를 `app/` 전체에서 검색해 범위에 넣는다. 표기를 바꿔 가며 찾는다(예: `÷ 3`, `/ 3`, `1/3`, `one third`).
   - 확인할 곳: 계산식, 안내문(notice), 입력 hint, 결과 라벨, FAQ, 본문, 표, 예시, 메타, 카드, schema, QuickCalc, 관련 링크 문구
4. 해당 페이지에 대해 history.md에 남아 있는 **알려진 오류**도 목록에 넣는다.
5. 검증 시작 전에 이 목록을 사용자에게 보여 준다.

**통과 기준:** 목록의 모든 항목에 파일 위치가 있다.

## 1단계. 코드 검증: 에러가 나지 않는가

```bash
npx eslint . ; echo "eslint=$?"
npx tsc --noEmit -p . ; echo "tsc=$?"
npx next build ; echo "build=$?"
```

- 종료 코드를 직접 본다. `| tail`을 붙이면 빌드 실패가 가려지므로 로그는 파일로 저장한다.
- `git diff --stat`으로 **의도한 파일이 실제로 바뀌었는지** 본다. 수정 스크립트가 조용히 실패한 적이 있다(2026-11-24).

**통과 기준:** 셋 다 0, 새 경고 없음, 변경 파일이 의도와 일치.

> 이 단계는 **내용이 맞는지를 전혀 보지 않는다.** 1단계 통과만으로 "검증 완료"라고 하지 않는다.

## 2단계. 화면 검증: 실제로 보이는가

1. 빌드 결과를 `npx next start -p 3100`으로 띄운다(백그라운드). 끝나면 반드시 종료한다.
2. sitemap의 모든 경로가 200인지, 없는 경로가 404인지 `curl`로 확인한다.
3. 범위에 든 페이지를 폭 1280, 500, 375에서 캡처하고, **이미지를 열어서 본다.** 스크립트는 localhost 외 접속을 모두 막는다(막지 않으면 로컬 검사가 실제 AdSense·GA에 기록될 수 있다). 다른 방법으로 로컬 화면을 열 때도 외부 접속을 막는다.

```bash
node scripts/verify-ui.mjs <임시폴더> home fence-calculator guides/how-to-calculate-roof-pitch
```

4. 스크립트는 HTTP 상태, 가로 넘침, 빈 화면, `undefined`·`NaN`, 사이트의 콘솔 에러를 자동으로 잡는다. 배치, 잘린 글자, 어색한 표시는 **이미지를 봐야** 알 수 있다. 전체 캡처에서 왼쪽 메뉴가 중간에 끊겨 보이는 것은 sticky 때문이다. 375는 Chrome 모바일 모드이며 실제 휴대폰·다른 브라우저는 미확인이다.
5. 확인: 빈 화면, 깨진 배치, 가로 넘침, 잘린 글자, `undefined`·`NaN`·`&apos;` 노출, 콘솔 에러, 이동하지 않는 링크.

**통과 기준:** 경로 전부 정상, 이미지를 직접 봤고 이상 없음, 사이트 코드의 콘솔 에러 없음.

## 3단계. 내용 검증: 공식·기준이 실제와 일치하는가

출처 기준은 `docs/content-rules.md` 1–3번을 따른다. 범위의 **모든** 공식, 수치, 조항, 안전 문구를 아래 표로 만든다.

| 사이트 문구 (파일:줄) | 원문 내용 | 출처·판·조항·URL | 확인일 | 판정 |
|---|---|---|---|---|

1. 오늘 기준 **현행판**을 먼저 확인한다.
2. 원문을 열어 읽는다. 검색 결과 요약이나 기억으로 판정하지 않는다.
3. 숫자뿐 아니라 **적용 조건**(지역, 대상, 단위, 최소/최대, 이상/초과, 예외, 의무/권장)까지 비교한다.
4. 공식은 변수 정의와 단위까지 비교한다.
5. 원문이 없는 관행은 rule of thumb으로 표시됐는지, 출처 없는 주장은 삭제됐는지 본다.
6. 원문이 막히면 아래 순서로 시도하고, 시도한 경로와 결과를 적는다.
   1. 발행 기관의 다른 공개 페이지나 PDF (PDF를 읽지 못했다는 보고를 받으면 저장된 파일을 `pdftotext -layout`으로 직접 연다)
   2. UpCodes의 **같은 코드·같은 판** 무수정 채택본. 다른 코드(IBC)나 다른 판·주 개정본의 비슷한 조항은 근거로 쓰지 않는다.
   3. 그래도 안 되면 조항 번호와 URL을 적어 **사용자에게 브라우저로 열어 문구를 전달해 달라고 요청**한다(ICC 사이트는 자동 접속이 403).
   4. 받기 전까지는 미확인.
7. 요약이나 대리 조회 보고는 잘렸을 수 있다. "없다"는 결론은 원문 목록을 끝까지 본 경우에만 쓴다.
8. 원문을 못 보면 미확인. 안전·구조 관련 수치가 미확인이면 완료로 처리하지 않고 사용자에게 알린다.

**통과 기준:** 모든 행에 판정이 있고 FAIL이 0.

## 4단계. 계산기 동작 검증

범위에 계산기가 있을 때 한다.

1. 정상값, 빈 값, 0, 음수, 아주 큰 값, 소수를 넣는다.
2. 모든 유형 탭과 단위를 바꾼다. 같은 길이를 ft와 m로 넣으면 결과도 같아야 한다.
3. 올림 경계(정확히 나누어떨어지는 값과 그 바로 위)를 확인한다.
4. **코드를 옮겨 쓰지 말고** **3단계에서 원문으로 확인한 공식**으로 `node -e`에서 따로 계산해 비교한다. 3단계에서 미확인인 공식은 "산술 일치"까지만 적고 내용 PASS로 세지 않는다.
5. 화면에 입력해서 나온 값을 본다(`node scripts/verify-ui.mjs <임시폴더> <경로> --steps steps.json`, 사용법은 스크립트 머리말). 코드만 실행했으면 "로직만 확인, 화면 입력 미확인"으로 적는다.

**통과 기준:** 정상값 3개 이상이 독립 계산과 일치하고, 예외 입력에서 에러나 이상한 값이 없다.

## 5단계. 예시·표 재계산

1. 범위의 모든 예시, 표의 **모든 칸**, FAQ 속 계산을 `node -e`로 실행한다. 일부만 했으면 어느 것을 했는지 적는다.
2. 반올림 방향과 중간 반올림 때문에 달라지는 값을 확인한다.
3. 기본 입력값과 placeholder도 예시로 본다. 예시가 현실적으로 가능한지 본다(2 m 벽에 2.1 m 문 같은 것).
4. 예시가 사이트의 안전 한도를 넘지 않는지 본다(한도보다 높은 담장 같은 것).

**통과 기준:** 실행 결과와 화면 값이 모두 일치.

## 6단계. 사이트 전체 일관성

1. 0단계의 검색을 다시 실행한다. 빌드된 HTML(`.next/server/app`)과 소스 모두에서 **옛 값 0건**인지 확인한다.
2. 계산식 ↔ 안내문 ↔ FAQ ↔ 본문 ↔ 표 ↔ 메타 ↔ 카드 ↔ schema가 같은 기준인지 비교한다.
3. 같은 주제의 다른 가이드를 **이번 검증에서** 열어 **반대로 말하는 곳**이 없는지 읽는다. 키워드 검색만으로는 찾지 못한다.
4. 글이 약속한 기능이 계산기에 실제로 있는지 확인한다.
5. 바뀐 페이지의 `dateModified`와 `app/sitemap.ts` 날짜를 확인한다.
6. 마지막으로 바뀐 페이지의 렌더된 본문을 **처음부터 끝까지** 읽는다.

**통과 기준:** 옛 값 0건, 모순 0건, 알려진 오류가 남아 있지 않음. 남으면 완료가 아니라 "일부 완료"다.

## 7단계. 보고와 배포 후 확인

보고 형식:

| 단계 | 판정 | 실행한 것 / 근거 | 남은 문제·미확인 |
|---|---|---|---|

- 첫 줄에 결론을 쓴다: 전체 통과 / 일부 미확인 / 실패.
- FAIL과 미확인을 먼저 보여 준다. 새로 찾은 문제는 범위 밖이어도 알린다.
- history.md에는 이 표의 내용만 적는다. 커밋·푸시는 작업 흐름이나 사용자 요청에 따른다.
- 배포했다면 실제 사이트에서 **바뀐 문구가 보이고 옛 문구가 없는지** 확인한 뒤, 바뀐 URL만 IndexNow로 제출하고 200을 확인한다.
